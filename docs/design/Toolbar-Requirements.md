# 工具栏需求文档

## 1. 背景与目标

当前编辑器的所有格式化操作（加粗、标题、引用等）仅能通过键盘快捷键触发（Ctrl+B、Ctrl+Shift+[ 等）。用户只能通过"视图→切换编辑模式"菜单或右下角按钮切换双栏/WYSIWYG 模式，界面中缺乏可视化的格式化按钮入口。

**目标**：为编辑器增加一个功能丰富的格式化工具栏，将快捷键能力以按钮形式可视化呈现，降低上手门槛，优化纯文本编辑体验。

## 2. 用户场景

1. **新用户首次使用**：打开编辑器后立即看到工具栏，能直观地了解编辑器支持哪些格式化操作
2. **鼠标用户**：习惯用鼠标操作，通过点击工具栏按钮完成格式化，无需记忆快捷键
3. **混合操作**：部分操作用快捷键（熟手），部分操作用鼠标（复杂组合），两者并存
4. **WYSIWYG 模式**：在即时渲染模式下，工具栏作为主要的格式化入口（部分标记符被隐藏时，用户无法直接输入语法）

## 3. 功能需求

### 3.1 工具栏按钮列表（优先级 P0-P1）

| 功能 | 图标 | 快捷键 | 插入效果 | 优先级 |
|------|------|--------|---------|--------|
| 一级标题 H1 | H1 | — | 在行首插入 `# ` | P0 |
| 二级标题 H2 | H2 | — | 在行首插入 `## ` | P0 |
| 三级标题 H3 | H3 | — | 在行首插入 `### ` | P0 |
| 加粗 | **B** | Ctrl+B | `**选中的文本**` | P0 |
| 斜体 | *I* | Ctrl+I | `*选中的文本*` | P0 |
| 引用 | ❝ | Ctrl+Shift+[ | `> 选中的文本` | P0 |
| 代码块 | `</>` | Ctrl+Shift+` | `` ``` `` + 换行 | P0 |
| 行内代码 | `c` | Ctrl+` | `` `选中的文本` `` | P0 |
| 无序列表 | • | Ctrl+Shift+L | `- 项1\n- 项2` | P0 |
| 有序列表 | 1. | Ctrl+Shift+O | `1. 项1\n2. 项2` | P0 |
| 删除线 | ~~S~~ | — | `~~选中的文本~~` | P1 |
| 链接 | 🔗 | Ctrl+K | `[选中的文本](url)` | P1 |
| 图片 | 🖼 | — | `![alt](url)` | P1 |
| 分割线 | — | — | 在行首插入 `---` | P1 |

### 3.2 非功能需求

| 需求 | 说明 |
|------|------|
| 工具栏位置 | 编辑器顶部，标题栏下方，始终可见 |
| 覆盖范围 | split 模式和 WYSIWYG 模式下均显示 |
| 工具栏高度 | 固定 40px，背景色跟随当前主题 |
| 按钮交互 | hover 时高亮，按下时执行格式化，无弹窗/下拉菜单干扰 |
| 提示信息 | 每个按钮 hover 时显示 tooltip，标注功能名 + 快捷键 |
| 按钮分组 | 按功能逻辑分组，组间用分隔线 |

## 4. 竞品参考

| 编辑器 | 工具栏位置 | 特色 |
|--------|-----------|------|
| Typora | 右键菜单 + 快捷键 | 无显式工具栏，极致简洁 |
| Obsidian | 编辑区顶部 | 紧凑工具栏，支持自定义 |
| Notion | 编辑区上方浮现 | `/` 命令菜单为主 |
| VS Code | 无 Markdown 工具栏 | 插件生态 |
| 语雀 | 编辑区顶部 | 丰富工具栏，分组清晰 |

**决策**：参考 Obsidian 和语雀，采用固定在编辑器顶部的紧凑工具栏风格。

## 5. 用户交互流程

```
用户选择一段文本（或置空光标位置）
       │
       ▼
点击工具栏按钮（例如「加粗」）
       │
       ▼
获取当前 CM6 EditorView 实例
       │
       ▼
执行对应格式化命令（dispatch changes）
       │
       ▼
编辑器内容更新 → 预览区实时刷新
```
