### 📅 开发与实施计划

**项目定位**：为个人开发的高质量本地版Markdown编辑器。
**总时长预估**：约 13~16 周。

#### 第一阶段：基础框架与环境搭建 (第 1-2 周)
*   初始化 Electron + Vite + React/Vue + TypeScript 项目。
*   配置好开发环境和热重载。
*   搭建主进程与渲染进程的基本框架，确保能显示一个简单的“Hello World”窗口。
*   使用 `electron-builder` 配置好基础打包脚本。

#### 第二阶段：编辑器核心与本地文件管理 (第 3-5 周)
这是项目的 MVP（最简可行产品）阶段。

*   **编辑器内核集成**：集成 ProseMirror 或 CodeMirror 6，实现文本输入、删除等基本编辑功能。
*   **Markdown 预览**：实现双栏预览模式。用 `markdown-it` 将编辑区内容渲染到预览区。
*   **文件操作**：实现新建、打开（单文件）、保存、另存为功能。使用 Node.js 的 `fs` 模块。
*   **实现基础菜单**：在Electron的原生菜单和应用内实现上述文件操作的入口。

#### 第三阶段：核心功能完善与体验优化 (第 6-10 周)
实现对主流 Markdown 语法的完全支持，优化用户体验。

*   **语法高亮**：集成 `highlight.js`，使预览区的代码块有高亮。
*   **数学公式支持**：集成 `KaTeX`，实现对 `$...$` 和 `$$...$$` 公式的渲染。
*   **表格支持**：支持 GFM 语法的表格渲染。
*   **文档管理侧边栏**：实现文件树/文件夹侧边栏，支持添加/删除/重命名文件。
*   **全局搜索**：实现当前打开文件夹的全文搜索功能（可先不做索引，直接遍历搜索）。
*   **快捷键系统**：实现常用快捷键（保存、打开、加粗、斜体等）。

#### 第四阶段：扩展功能与主题定制 (第 11-13 周)
在这个阶段，你可以根据个人需求，开始实现那些使编辑器更强大的功能。

*   **导出功能**：实现导出为 HTML 和 PDF（PDF可通过打印功能或 `puppeteer` 实现）。
*   **主题系统**：实现动态切换 CSS 主题的功能。
*   **图表支持**：集成 `Mermaid`，实现对流程图、时序图等图表的渲染。

#### 第五阶段：高级功能与优化 (第 14-16 周)
*   **即时渲染模式**：尝试实现更具挑战性的“所见即所得”模式（如果项目目标是高度还原Typora，此阶段为必须）。
*   **专注模式**：实现段落高亮或背景置灰功能。
*   **性能优化**：针对大文件、重复渲染等场景进行性能调优。
*   **Bug修复**：全量测试，修复各功能模块的Bug。

### 📐 四、详细设计文档计划

在正式编码前，建议为以下每一个核心模块都编写详细的《技术设计文档》，作为开发的蓝本。

1.  **核心文档：即时渲染设计文档**
    *   **目标**：阐明如何实现类似Typora的“源码标记隐藏/显示”机制。
    *   **内容**：
        *   定义`文档树`节点类型，特别是`SyntaxMarker`的设计。
        *   设计`Decoration`插件，如何根据光标位置动态应用样式。
        *   定义`解析器 (Parser)` 和`序列化器 (Serializer)` 如何与文档树交互。
        *   描述具体的`编辑事务`（如键入`**`加粗标记）是如何流转和生效的。

2.  **基础模块：文件系统模块设计文档**
    *   **目标**：定义应用如何与本地`文件系统`安全高效地交互。
    *   **内容**：
        *   定义`FileService`服务，封装`fs`模块的所有操作。
        *   规定`IPC`通信的通道名称和数据结构（如`file:open`, `file:save`）。
        *   设计`文件状态管理`，如何在渲染进程中管理当前打开文件的状态。

3.  **功能模块：侧边栏（文件树/大纲）设计文档**
    *   **目标**：实现一个高性能、可扩展的侧边栏组件。
    *   **内容**：
        *   定义侧边栏的两种模式：`文件树模式`和`大纲模式`。
        *   设计`文件树`的数据结构（如何高效表示嵌套目录）。
        *   设计`大纲`的数据结构（如何解析文档并提取标题层级）。
        *   定义侧边栏与编辑器核心的`交互事件`。

4.  **核心功能：预览与渲染模块设计文档**
    *   **目标**：定义如何将Markdown文本转换为最终的HTML预览。
    *   **内容**：
        *   定义`渲染管线`：`Markdown文本` -> `markdown-it` -> `HTML` -> `渲染`。
        *   设计`markdown-it`的`插件配置`，包括代码高亮、公式、图表等。
        *   定义`预览区`和编辑器核心的`联动`机制（如双向滚动）。

5.  **系统级：扩展与插件系统设计文档 (可选)**
    *   **目标**：如果计划未来实现插件系统，需要提前做架构预留。
    *   **内容**：
        *   定义插件的`生命周期`（加载、初始化、卸载等）。
        *   设计插件可用的`API集合`（如注册命令、添加菜单、添加语法高亮规则等）。
        *   定义插件的`加载机制`（扫描目录、动态加载）。
        *   `安全沙箱设计`

为了让这份计划能真正落地，一开始确保各个模块都有灵活的风险应对方案和接口设计尤为重要。
